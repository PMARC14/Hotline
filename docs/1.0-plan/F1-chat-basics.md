# Job F1: chat basics for 1.0 (branch feat-f1-chat)

Follow W.md (common rules) in the same folder. New strings go right after the key `Set_ChatWidth_Desc` in each resx. Hotline is a quick-question tool, so these must be light and keyboard friendly; look at how Chat/ChatPresenter, ChatController, HistoryStore, RecentChatsMenu, TranscriptView and Composer work today before designing.

Build (Core first with tests, then App):
1. **Edit and resend**: edit your last user message (also any earlier one): the transcript from that message on is dropped and the edited text is sent again (attachments of that message are kept and can be removed). UI: an "Edit" action on a user message (hover/menu + keyboard: Up arrow in an empty composer edits the last message), puts the text and attachments back in the composer in "editing" state with a clear way to cancel; the old turn is cancelled if still streaming. Core: `ChatController.Edit(index)`-style API with tests (history truncation, CLI-session connections: an edit/regenerate on a connection with a kept CLI session must start a NEW session or resend the whole transcript as the existing "context" mechanism does: read CliSession/HasWholeTranscript code and make the behaviour correct, document it).
2. **Regenerate** the last answer (and after an error: the existing Retry stays): same connection or pick another connection/model from a small menu; the previous answer is replaced (kept in memory as "previous version" only if cheap; otherwise dropped).
3. **History search**: search box in the recent-chats menu/list filtering by title and message text (case-insensitive, diacritics-insensitive, runs off the UI thread with a cap and cancellation; Core `HistoryStore.Search(query, limit)` with tests incl. damaged files skipped and no full-file loads for huge histories (stream/limit)).
4. **Pin / star chats**: a pinned flag in the history meta (backward compatible reading: missing = false); pinned chats list first and are exempt from retention pruning (`historyRetentionDays`); UI toggle in the chat list and a command in the chat menu; tests including pruning.
5. **Export a chat as Markdown**: "Copy as Markdown" (clipboard, user-initiated button only) and "Save as .md" (FileSavePicker like the Backup page; write via temp file + move). Core `ChatExport.ToMarkdown(transcript, options)` with tests: roles, code fences that contain backticks, attachments listed by name (never inline file contents or images), tool calls summarised, no secrets, deterministic output; file names sanitised.
6. **Context / token meter**: a subtle indicator near the composer (e.g. "~3.2k / 200k" on hover or small text) estimating tokens of the current conversation (chars/4 heuristic is fine; use real usage numbers if a backend already reports them) against the model's context window (extend `ModelFamilies`/ConnectionTypes with a documented context-window table for known models; unknown = no meter) and turning a warning colour above ~80%; setting `chat.contextMeter` ("auto" | "off", default auto) in settings + Settings page, localized. Core `ContextMeter` with tests.
7. A setting-free quick path: Ctrl+Shift+C copies the last answer (check it does not clash with existing shortcuts; if one exists skip), documented in docs/TESTING.md.

Everything user-visible is localized (English placeholders) and has an AutomationProperties.Name. Guard every async void with try/catch+notice. Docs: configuration.md (`chat.contextMeter`, pinned history field, export), TESTING.md manual lines. Report as W.md says.
