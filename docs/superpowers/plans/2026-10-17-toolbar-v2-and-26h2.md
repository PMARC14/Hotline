# Hotline 0.4: button rows v2 and the 26H2 pass — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.4: `toolbar.json` v2 (four quadrants, size/outline/filled styles, custom buttons) with a drag-and-drop Settings editor and a validation layer that hand-edited files cannot break, drop Hotline's Right Ctrl mode, default width 680, and the 26H2 wording/doc fixes.

**Architecture:** All reading, validating, migrating and editing of the button rows is pure code in `Hotline.Core/Windowing` (`ToolbarModel`, `ToolbarEditor`, `ToolbarFile`, `ToolbarLayout.Fit`), unit-tested and fuzzed. The app renders only a resolved `ToolbarModel` (`PopupWindow.ApplyToolbar`), and the Settings editor edits only through `ToolbarEditor`, so neither can produce or consume an invalid file. Settings schema v14 archives the old files as `<file>.old` and leaves connections untouched.

**Tech Stack:** C# / .NET 10, WinUI 3, xUnit (`dotnet test`), System.Text.Json, 17 `Strings*.resx`.

**Spec:** `docs/superpowers/specs/2026-10-17-toolbar-v2-and-26h2-design.md`

## Global Constraints

- Branch `windows-26h2` (PR #9); never commit to `main`; commits authored `pmarc14 <16502495+PMARC14@users.noreply.github.com>`; **no Claude co-author trailer / PR footer**.
- TDD in `src/Hotline.Core`. Test command: `dotnet test --project tests/Hotline.Core.Tests/Hotline.Core.Tests.csproj` (filter with `--filter-class`/`-- --filter-method` as the project's runner allows; run the full suite before each commit that touches shared code).
- Archive = keep the file beside the new one with `.old` appended (`settings.json.old`, `toolbar.json.old`; next free `.old2`, `.old3` … never overwrite an archive). Not `.bak`, not `backups\`.
- **Connections must not break:** `connections/*.json` and `defaultBackend` are carried over unchanged; API keys (Credential Locker) untouched; a connection file that cannot be converted is left as is and reported.
- Default panel width **680**. Size presets (DIP, icon buttons): compact 30×28 font 13 · normal 36×32 font 15 · wide 46×32 font 15 (finalise from self-test PNGs). Per-item width/height clamp 20–80.
- Clamps: labels ≤ 40 chars, control chars stripped; text actions ≤ 2000 chars; ≤ 24 custom buttons; ≤ 40 items per quadrant; icon = hex `E000`–`F8FF`, 4–6 digits; custom id `[a-z0-9-]{1,32}`, never a built-in id. Strings from the file are never markup, paths or commands (`quickAction` = a name looked up in `actions\`).
- Pickers (`effort`,`model`,`provider`) stay one block; they ignore size/outline/filled. Never change sizes inside a size event; queue via `QueueLayout`; set values only when changed (HANDOFF "LayoutCycleException").
- Testing on the owner's PC: panel and windows closed afterwards; no keystrokes, clipboard or visible windows without asking; prefer `hotline://selftest`. Back up and restore any settings/toolbar file a test changes.
- Reviews: `agy --model gemini-3.8-flash-high -p "<prompt>"`, diff pasted in the prompt, "answer from the text below only, do not call any tool", chunks < 32k chars, never keyboard-hook/SendInput code on a command line. Verify each finding against the code before fixing.
- New user-visible strings go in `Strings.resx` and all 16 other `Strings*.resx` (translated; Gemini 3.8 Flash checks); new features get Guide text.
- Out of scope: Phi Silica / Windows AI connection, `odr.exe` discovery, agent workspace, Ask Copilot, new App Actions work. Default layout is decided later (defaults stay today's layout).
